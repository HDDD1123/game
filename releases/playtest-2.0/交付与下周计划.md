# 桌面王国 · 可玩测试版 2.0

[下载 Windows x64 试玩包](KingdomDesktop-2.0-Windows-x64.zip) · [SHA-256](SHA256SUMS) · [操作与存档说明](../../apps/desktop/启动说明.txt)

解压全部文件后运行 KingdomDesktop.exe。建议第一次试玩依次体验街景推进、收取成熟粮食、处理流民、改善农业、研究技能、管理窗口出征，然后保存、退出、重启并读取。在线自动走时可在管理窗口开启，每 150 秒结算一个月；事件与关闭确认会暂停时间。

## 实际验证

使用 Godot 4.6.3.stable.official.7d41c59c4，官方导出模板以同版 SHA-512 清单校验。独立用户目录内完成工程导入和 Windows Desktop release 导出。

- 源码的 17 组共 507 项检查通过。含核心经营、远征、旧档迁移、两种界面、时钟、内容目录、回放、平台、叙事和 12 项新场景回归。平台负例输入了三份非法 JSON，运行器记录解析诊断，负例断言通过。
- 对最终 ZIP 复核 SHA-256，解压到空目录。确认 EXE 是 x86-64 PE，使用 Linux 版同版本 Godot 从解压出的 PCK 启动主场景，再执行新局续玩 12 项、街景操作 24 项、存档及玩法回归 63 项，全部通过。三组是对成品的重复验证。
- 图形环境限定的原生置顶检查跳过。Windows 双击冷启动、真实鼠标、任务栏、副屏、125% 缩放以及连续两小时资源占用均待实机验收。

复验时在仓库根目录运行 `godot --headless --path apps/desktop --import`。逐个运行 `apps/desktop/tests` 下的 GDScript 测试。导出命令为 `godot --headless --path apps/desktop --export-release "Windows Desktop" <输出目录>/KingdomDesktop.exe`。在空目录解压 ZIP 后，可用 `godot --headless --main-pack KingdomDesktop.pck --script <源码绝对路径>/apps/desktop/tests/test_playtest_20.gd` 复验成品。测试使用独立的用户数据目录。

## 11 月 23 日至 29 日四机计划

周一四机用同一份 2.0 ZIP 和 SHA-256 开工。首轮缺陷附构建号、操作步骤、实际与期望结果、可复现存档或截图。崩溃、坏档、无法完成主循环优先于新玩法。各机从本次交付另开工作分支，修复按文件归属交给中控整合。

| 负责人 | 周一至周三（23–25 日） | 周四至周五（26–27 日）验收交付 |
|---|---|---|
| DSH1 · UI | 在 Windows 按试玩路线实际点击。优先查找流民暂停后进不去、菜单遮挡、读档后按钮失效。覆盖 720/960 宽与 100%/125% 缩放 | 交付 UI 修复、每种布局截图及一段真实鼠标录像。首次玩家须能从新局走到研究、远征、退出和续玩 |
| DSH2 · 核心与存档 | 复核在线跨月与手动推进结果、待决事件、关闭取消、战斗中保存。以 v3/v4/v5 和坏 v5 各留一份可复现样本 | 同一条命令序列分别直接执行、在途保存后继续执行，比较资源、农田、远征和月份。验证坏档保留现场，交回样本、回归脚本与结果 |
| DSH3 · 经营试玩 | 用现行规则走两条路线：收粮经营、派兵探索。逐月记下第一次缺粮、首次技能、首次出征与返回时的资源；记录卡死或信息误导的最短操作序列 | 交付两份可重放记录和关键节点存档；复跑到结局或约定终点并说明原因。候选数值另列对照，不改本轮基准 |
| DSH4 · Windows 包与运行 | 干净目录双击 EXE，在单屏和副屏测试启动、任务栏边界、置顶、关闭取消、保存退出及重开。记录系统版本、分辨率与缩放 | 对候选包做两小时在线长跑，按固定间隔记录 CPU、内存、窗口响应及存档恢复；交付包哈希、日志、实测矩阵和未测项 |

周末（28–29 日）由中控收敛同一候选包。先回归阻止启动、结算或续玩的缺陷，再由另一台机器从空目录复走全程。完整试玩、退出重入及坏档保护均通过后，冻结可供下一轮试玩的 ZIP、校验值和复现记录。实机未通过项保留原始证据、负责人及复测条件。
