二、目标
让小组成员从干净目录双击一个 ZIP 解压出的 EXE，能开始新内容、继续旧局、看懂选择的结果，并用同一包复现问题。
全组目标为 11 月 29 日（周日，北京时间）交付 Windows x64 试玩版。首局有效体验目标 45–60 分钟，换线新增体验目标 20–30 分钟；由真人试玩记录决策与等待。两条路线须能从新局走到阶段小结，中途退出后能续玩。

三、十二个工作包（各6点，交可执行成果与验证）
T4-01  基线导出｜校验 Godot 4.6.3 模板，从固定提交导出 Windows Desktop release。解压到干净目录，记录 EXE/PCK、启动表现与 ZIP 哈希。
T4-02  新局与继续｜提供可装配的首屏组件，说明基础旧局和 2.1 新内容入口。分别测试首次启动、有效旧档与损坏新档的真实反馈。
T4-03  首次向导｜用玩家实际收粮、升级、处理流民等证据推进提示。验证跳过、重看、新局和继续的行为；向 DSH1 交接入口。
T4-04  双线手记｜为粮贸与边境各做可回看的阶段小结。为同一事件的不同选择给出对照，只有已有事实才写入史书。
T4-05  集成出包｜周四从中控固定的整合提交导出完整包，核查建筑素材、内容 JSON、叙事文件和主场景都可加载。
T4-06  窗口与输入｜在 Windows 从干净目录双击，真实鼠标走农田、交易和派驻；测置顶、关闭取消、100%/125% DPI 及副屏。记录系统、分辨率和设备条件。
T4-07  保存退出与恢复｜在远征、驻守和待决事件中分别保存并退出，从同一 ZIP 重启读取。确认较新坏档保留、旧档可继续，记录可复现步骤。
T4-08  交叉试玩准备｜周四约好两名验收者，准备两张路线记录表和一个中途退出点。周五按表各从新局走完一路并交叉换线，记录实际用时、纯等待、卡点和结算截图。
T4-09  两小时长跑｜用当轮候选包实测两小时，定期采 CPU、内存、窗口响应；检查挂起恢复、后台在线走时和事件暂停，交采样时间点与日志。
T4-10  阻塞复测｜把崩溃、坏档、主线卡死优先交责任机。修复后以新哈希重新验证受影响路线；周六同一候选包完成两线及实机验收。
T4-11  玩家材料｜交一页启动和存档说明、变更清单及反馈表。反馈包含构建号、路线、用时、复现步骤、预期与实际、截图或复现存档。
T4-12  最终包｜周日将最终 Windows x64 ZIP、SHA-256、对应源码提交、测试矩阵和已知问题交中控核对，再由中控交给小组。
