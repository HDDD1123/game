# 任务3：经营平衡实验、资源曲线与回放工具

负责人：新DSH-B。分支：`dsh/task3-balance-v05`。目标：交付可反复运行的工具，找出资源过剩、人口流失和技能点闲置从哪一阶段开始，并用数据比较两种小幅调整。

先读 [总览](四机并行总览.md)、[接口约定C](四机接口约定.md) 和现有core。使用 `godot-gdscript-headless-testing`，分析与报告可参考 `prototype-fast`；不把通用增量游戏公式当作本项目规则。12点，四个里程碑各3点。

## 里程碑1：模拟与操作记录器（3点）

- 在 `apps/desktop/tools/balance_lab/` 实现可命令行运行的策略模拟器，使用真实Kingdom的 `act/snapshot/view` 和报价，不复制一套结算公式，也不直接改 `_state`。
- 每次操作记录月份、命令/参数、成功与原因、人口/粮仓/待收/木材/矿石的前后值与净变化；记录建筑等级、三树可用技能点、远征状态、累计饥饿/战斗死亡。净变化必须标成净值，不能冒充总产量/总消耗。
- 输出CSV与JSONL、源码提交与配置指纹；操作记录可通过公开act回放，对比最终snapshot。拒绝的操作也保留；死局停止并给原因，不无限等资源。
- 正常模拟从新局开始，不注入资源。专门边界fixture可以有，但与经营数据分开，明确标注。

## 里程碑2：六组可比较经营过程（3点）

- 三条策略：少接纳/先农业；多接纳/先住房；先废墟远征/再铁匠铺。把接纳、建造、研究、派兵的决策写成明确规则和优先级，不能运行后挑好看的结果。
- 每条各跑“每月收粮”和“每三个月收粮”两种频率，固定策略下检查收获间隔的代价。待决流民必须按策略处理后才能继续；每月最多执行有限数量操作，防止升级/拒绝循环卡死。
- 共六组推进至120个月或王国结束，标出6/12/24/36/120月；若提前覆灭，后续填未到达而非补造数据。输出第一次短缺、首次死亡、地下城突破、首次闲置技能点及长期无用途资源。
- 定义可计算的“资源无去处”观察指标，例如连续若干月储量上升且策略无可执行支出；说明这是该策略下的现象，不能据此断言所有玩法必然如此。用标准绘图库出独立PNG/SVG曲线，不调用图像生成画数据图。

## 里程碑3：两套单变量候选实验（3点）

- 基线结果出来后选择一个被证据支持的数值族，例如农业升级价格；提供两个候选配置，与基线使用完全相同六条策略重跑。每套只改这一族，记录改前/改后值和理由；没有支持改动的证据时照样做敏感性实验并说明不建议采用。
- 候选存 `apps/desktop/data/balance_proposals/`，**不改生产balance.gd**。实验脚本在临时目录复制必要Godot工程，按白名单只替换候选常量，确认每项只匹配一次；保留引擎/源码/配置指纹，运行真实规则。不要在原工作树先改再恢复，也不要把.git、存档或凭据复制进实验目录。
- 对比生存/饥饿、发展速度、库存和选择代价；不要靠让全部路线饿死来宣称解决资源过剩。指出价格调整解决不了的结构问题，如只有3节点导致技能点没有用途。
- 给出最多三条后续建议，区分“有数据支持的数值改动”和“需要设计的新建筑/消耗”。本轮不实现魔王、维护费或未经确认的随机惩罚。

## 里程碑4：回放、检查与短实玩（3点）

- 在 `apps/desktop/tests/task3/` 验证记录回放一致、重复运行确定性、候选不改原工程、非法参数拒绝、策略停止条件。添加能发现人口/资源为负、失效事件重复受理等异常的检查，不把同一公式抄进测试。
- 选一个关键瓶颈案例，用主界面公开操作重现，记录步骤与截图/短视频；若只有脚本可运行，则交完整回放明确未实玩，不编造感受。所有路线都未遇到危机也是真实结论。
- 在 `apps/desktop/docs/交付/任务3/` 提交小型CSV、图表、关键回放与README；海量中间输出放本地dist。README给出一条可复现命令、来源提交、三条最重要结论、候选差异和局限。

## 边界与完成标准

只新增 `apps/desktop/tools/balance_lab/`、`tests/task3/`、`data/balance_proposals/` 和自己的交付目录。core、UI、既有tests与全局配置只读；不为注入候选数值改生产接口。

固定基线的旧手动月结算足够立即开工；报告明确其不能证明任务2连续生长后的平衡。交工具时提供如何在任意指定检出版本重跑的命令，GPT整合后再生成新版本数据。完成的是可运行、可回放的实验工具和证据，而不只是文字建议。
