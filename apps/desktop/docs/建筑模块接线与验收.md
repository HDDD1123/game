# 任务005接线规则

两个新模块无Node、Timer、系统键盘或文件操作，可独立测试。本分支还未把它们接到主场景。

## 数据与职责

- BuildingSkills：解锁条件、点数检查、累计效果与技能子状态。
- FarmBuffer：整数生长进度、最多3批成熟粮食、活动加速额度、收取与生产子状态。
- Kingdom：资源、建筑等级、日历、暂停判断、命令入口，负责组合两个模块的结果。
- SaveStore：完整状态保存、格式迁移与失败回滚。
- UI：显示Kingdom.view()并发出命令；不单独持有一份技能点、粮食或生长计时器。

## 新命令与只读显示

在Kingdom.act中添加：

| 命令 | 参数 | 行为 |
|---|---|---|
| harvest_farm | 无 | farm.collect()返回多少，粮仓就加多少；0不能制造收益 |
| assist_farm | source为click或typing，count为正整数 | 根据当前每批产粮和暂停状态调用farm.apply_activity；不直接加粮 |
| unlock_skill | tree、node | 由Kingdom根据对应建筑等级计算累计点数，调用skills.unlock |

禁止UI传入earned_points、粮食数、技能效果或进度值。所有增益由模块计算。主点击优先收获；没有待收时才发assist_farm。研究入口独立。

view补充：farm.view()、技能目录、每树累计/已花/可用点、解锁状态、有效住房容量和生效后的产量/费用。现有state.housing作为基础容量保留，显示与接纳判断改用skills.housing_capacity(state.housing)。

## 数值计算

每批基础粮食仍为12+(农业等级-1)×6，再交给skills.farm_yield(base_food, drought_factor)。普通季节factor=1.0，旱季factor=0.6。该函数先加每批增益，再乘旱季系数，最后向下取整。

- skills.natural_growth_points(10000)：本游戏月自然生长工作量。
- skills.wood_production(城内人口, 0.6)：每月木材，只在最后取整。
- skills.expedition_attack(2+铁匠铺等级)：出发时锁定的单兵战力。
- skills.expedition_wood_cost(人数, 1)：出征木材总费用，向上取整。

已成熟批次保存当时产粮，不随以后升级或季节回溯变化。出发队伍已锁定的attack仍不随升级改变。存档中的合法attack上限需覆盖原等级上限加技能加成，不能继续写死为5。

## 月结算顺序（本轮没有自动时钟）

1. 按月初状态计算城内人数、正常/旱季每批粮食、自然工作量、粮食需求和木材产出。
2. 允许推进且城内有人时，调用farm.grow_naturally(工作量, 每批粮食, false)。作物进入待收区，不加粮仓。
3. 从粮仓扣居民口粮，按现有规则处理短缺与伤亡。粮食可用量只看库存，不能再次加每批产量或待收粮食。
4. 增加月份、处理存活队伍战斗、失败与流民事件，沿用现有先后逻辑。新月份调用farm.begin_month(state.months)重置该月加速额度。
5. 渲染待收、库存、风险及事件。若库存不足而田里有粮，提示“粮食还在农田，请先收获”，不能暗中替玩家收割。

事件暂停或失败时不得调用生长与加速。收取已经成熟的粮食不推进时间，可以在流民决策期间进行；结束的王国不再允许改变资源。所有这些检查在Kingdom入口执行，不只置灰按钮。

## 点数来源

农田累计点数=agriculture；铁匠铺累计点数=forge；民居累计点数=housing_level。新增housing_level初始1，每次原有扩建住房成功后+1。点数余额由累计点数减已解锁数计算，不再单独保存一份会重复扣加的余额。

每棵树的基础节点1点，两条分支各1点，均最多解锁一次。两分支可先后获得，不互斥。本轮没有重置、退款或跨局继承功能。

## 存档与迁移

采用新完整存档格式4与user://kingdom-save-v4.json，保留现有格式3文件。SaveStore读格式4；仅在尚无格式4文件时允许明确提示并迁移原格式3。格式4损坏时不能悄悄退回旧局。

格式3迁移前先校验旧结构，再生成：

- 空的技能解锁状态，累计点数由现有建筑等级决定。
- housing_level=max(1, 1+floor((基础住房-14)/6))。
- 空的待收区、0生长进度、0已用加速，farm.month=原state.months；不追补历史产出。

完整格式4包含Kingdom原有字段、housing_level、技能snapshot和农田snapshot。先在临时对象中同时校验基础状态、模块状态与跨字段关系，全部有效后再替换当前局。需要检查farm.month与日历一致、已花点不超对应等级、人口不超有效住房，以及远征attack范围等。

读取后不重新执行技能奖励；容量和产量始终由基础数值加modifiers派生，避免叠加。UI和关闭保存流程统一使用新的SaveStore入口，不能一处写v4、另一处仍写v3。

重新开始时同时创建全新的技能与农田模块，并重置housing_level；不能只重置旧Kingdom字段，留下上一局的待收作物、加速额度或已解锁技能。本轮尚无跨局继承。

## 固定验收场景

以下场景从新局开始，未点任何技能，且只执行说明中的操作：

1. 初始人口10、住房14、粮仓30、木20，待收0。
2. 推进一月：第1年2月，粮仓20、木26、待收12（1批），4人流民待决定。粮仓不能仍显示32。
3. 决策暂停时收获：粮仓32、待收0。立即再次收获，粮仓仍32。
4. 接纳4人后推进一月：第1年3月，人口14、粮仓18、木34、待收12。收获后粮仓30。
5. 另一新局每次拒绝流民，连续3个月不收获：第1年4月，粮仓0、待收36（3批）；再推进会有缺粮风险，界面必须清楚提示。
6. 3批满时反复加速不增粮、不存隐藏进度。收取36后从当前剩余进度正常继续，不能补发过去停产的粮。
7. 农田升到2级后累计2点。先点精细采收再点灌溉：正常每批20，旱季每批16；旧的已成熟12粮批次保持12。
8. 基础住房14，解锁屋梁与阁楼后有效容量20；保存读回仍20，不能变成26。
9. 基础单兵战力3，解锁锻造与兵刃后，新队伍战力5；既有在途队伍仍保持原attack。
10. 存档包含部分生长、两批不同产量、已用活动额度和未处理流民；关闭读回后各项一致，下一次收取总量正确且仅入库一次。
11. 在有待收作物和已解锁技能时重新开始：粮仓30、待收0、进度0、三树均未解锁，初始点数来源正确，旧手动存档仍保留。
