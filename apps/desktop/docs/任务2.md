# 任务2：自动走时、连续生长与月中存档

负责人：新DSH-A。分支：`dsh/task2-clock-v05`。目标：让农田在在线时间中自然生长，统一处理月结算、暂停与保存，消除“只能点月份才能生长”的限制。

先读 [总览](四机并行总览.md) 和 [接口约定A](四机接口约定.md)。目标接口和150秒/月已由GPT定义，按此实现；保留已确认玩法，不另改人口/战斗/价格。按路由读取 `godot-gdscript`、`save-systems`、`godot-gdscript-headless-testing`。

工作量12点：时间入口4点，生长/月界3点，存档3点，独立演示与交付2点。无需等待任务1。

## 里程碑1：统一时间内核（4点）

- 新增 `apps/desktop/core/game_clock.gd`（RefCounted），由Kingdom持有。实现约定的tick、自动开关、外部阻塞与view.clock，不在core放Timer、Node、系统日期或文件访问。
- 细分时间与手动“推进到月末”走相同计算路径。自动开启时拒绝手动跳月；事件/结束/外部阻塞正确阻止推进，失焦不自动暂停。
- 时间中止不积攒补算；退出、系统睡眠/长卡顿恢复不瞬间消耗数月口粮。遵循接口约定中的增量上限和余量算法。

## 里程碑2：连续生长与月界结算（3点）

- 将原 `_advance_month` 的整批自然生长拆到统一时间入口，月末只结算剩余逻辑，避免重复生长。
- 保持技能影响、季节切换、待收上限、手动收粮、加速共享额度、归队才入库以及饥饿先于战斗。
- 月内中途升级或点击，只影响之后的工作/成熟批次；不可重新给已经生产的时间发放奖励。
- 用无场景测试证明分步与整段等价，尤其149999→150000毫秒、满田后收取、跨旱季、暂停后恢复和事件发生后的余时丢弃。

## 里程碑3：格式5与旧档迁移（3点）

- 更新 `core/save_store.gd` 和Kingdom导入方法，实现约定的v5字段、默认路径、4/3迁移及损坏文件行为。
- 使用独立fixture验证：正常v5往返、月中/远征中/有事件的存档、v4和v3迁移、v5缺clock/非法分数/越界字段、v5坏但v4好、新旧文件同时存在、显式路径不串读、保存失败不破坏原档。
- 读取失败保持当前资源、时间和自动运行状态；成功读取暂停，等待玩家开始，不读取墙上时间补算。旧档本月已用助耕额度保留。
- 不加自动存档、不自动恢复.bak，不删旧档；skill里的通用建议服从本项目约定。

## 里程碑4：独立可运行演示（2点）

- 在 `apps/desktop/experiments/task2/` 做独立场景，显示月内进度/农田/粮仓、开始/暂停、收获、手动月末、事件处理、临时保存/读取；使用真实Kingdom，全部调用公开接口。
- 启动例如 `Godot.exe --path apps/desktop res://experiments/task2/clock_demo.tscn`，不要改project.godot的主场景，也不要改主界面的main.gd。演示默认不自动开始，避免覆盖玩家进度。
- 驱动用单调时间短增量，保持小数毫秒余量；UI状态刷新节流到每秒最多4次或重大操作后更新，不每帧重建面板。测试可直接调用tick快进，标记为模拟时钟。
- 输出 `apps/desktop/docs/交付/任务2/README.md`，说明实际接口、迁移策略、运行命令、验证日志摘要、仍待GPT接到主街景的部分。
