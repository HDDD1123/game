# 任务2：时间、存档、人才运行与稳定性（72点）

负责人：新DSH-A。分支：`dsh/task2-clock-v05`。修订R2。目标是实现统一且可保存的运行内核，承接新玩法而不让时间、资源、自动化重复结算。

先读 [总览](四机并行总览.md)、[接口](四机接口约定.md)、[研究规范](同类游戏调研与特色设计规范.md)。按阶段读 `godot-gdscript`、`save-systems`、`godot-gdscript-headless-testing`；性能阶段补相应技能，不一次加载全部。12包各6点。

## 实现约束

- core无Node/Timer/网络/文件访问（SaveStore负责文件）；生产驱动位于 `apps/desktop/runtime/`，由唯一SessionController掌控。UI、启动服务、后台输入均调用同一公开命令路径。
- T2-04开始就预留版本化extensions；不能让T2-05以后每加一个模块就破坏同版存档。旧clock-only试验v5若已在本地生成，保留fixture并写明迁移规则，不覆盖原档。细则见接口扩展段。
- 人才使用共享人口池和固定角色ID，不按性别硬分生产效率；总人口含驻军和在途，死亡才扣人口。完整出生/儿童成长/居民养老与继承人40年剧情只做方案或独立受控原型，不把尚未验证的人口模型强塞进基础存档。
- 个性影响有边界且可预览：出征后依然没有玩家任意召回；将军按事先说明的条件在房间边界决策。资源不足或权限不足时停止并解释，不能反复尝试刷日志。
- 暂停/结束/已满时输入奖励不能堆积，自动化不能跨暂停偷结算。每条月度自动任务具备幂等标识和有界次数；所有随机过程保存状态，不调用全局随机让重载结果漂移。
- 不主动更换引擎、增加联网存档或离线收益；普通业务修复可按授权直接进行。结构性新规则只进入可选择的预览内容，在报告中说明影响。

## 修改范围与交付

负责 `apps/desktop/core/`（排除任务3的`core/content/`）、`runtime/`、`tests/task2/`、`experiments/task2/`，及必要的原8组测试调整。可适配balance与building_skills，但数值改动必须来自可复现候选对比，不能为了测试全绿强行换规则。主UI、平台助手、内容数据只读。

每阶段在 `apps/desktop/docs/交付/任务2/` 交delivery.json、接口差异、迁移样例/命令、关键不变量结果和未测项。保存测试使用独立目录，含读写失败保持内存状态的证明。至少有一个可运行时钟/事件/人才演示，最后与任务1共同验证主场景。
