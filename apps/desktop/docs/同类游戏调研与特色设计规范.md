# 同类游戏调研与特色设计规范

日期：2026-11-13。用于72点版任务1—4。目标是把参考作品的设计方法转成适合本游戏的可测试方案，不堆游戏介绍或换名复制。

## 四机分开取材

| 任务 | 候选参考作品 | 要回答的问题 |
|---|---|---|
| 1：画面与操作 | Rusty’s Retirement、Kingdom Two Crowns、Thronefall | 小区域如何读懂状态？建筑/单位如何一眼识别？哪些操作值得直接点，哪些应收进面板？ |
| 2：运行与系统 | Melvor Idle、Cookie Clicker、(the) Gnorp Apologue | 等待与操作怎样分工？瓶颈怎样出现？何时值得自动化，如何解释暂停、结算与增益？ |
| 3：经营内容 | Against the Storm、Kingdoms and Castles、Banished | 建筑怎样改变资源流向？人口/生产/防御如何竞争资源？危机怎样提供不同解法？ |
| 4：向导与叙事 | Yes, Your Grace、Reigns、Kingdom Two Crowns | 选择怎样预告代价？人物怎样留下记忆？结果怎样转成可信的王国历史？ |

以上是待调研名单，不是已经核实的玩法结论。每机至少深入2款，第3款用于补一个具体问题；允许找到更贴切的作品替换并说明原因。优先官方商店/说明、开发日志，再用可靠实机视频或评论补充。无需买齐游戏，不能自动消费预算。

每条参考观察记录：游戏名与版本（能确认才写）、来源URL、查阅日期、视频时间点/页面位置、观察到的机制、证据类型、为何适合/不适合本项目。亲自玩过才写“实玩”；仅看视频就写“视频观察”。查不到的信息标未核实，不伪造销量、平均时长、截图或胜率。

每款交3条可定位的观察，总共至少6条；每条都配一个可执行设计启示。不要求长篇报告。候选素材可来自公开机制研究，但不搬用别人的图片、名称、角色设定、代码或整套技能数值。

## 每台的候选数量与归属

每台交 **6个特色建筑、4种特色单位、12个技能效果**，分别用`T1-`至`T4-`前缀编号。任务1偏建筑外观与操作方式，任务2偏生产/调度/自动化，任务3偏资源瓶颈与远征，任务4偏人物/事件/历史。候选可以交叉协同，不用为了凑数量把同一机制换三个名字。

所有候选放自己的 `apps/desktop/docs/交付/任务N/创意候选.md`；可另附结构化JSON。任务3汇总去重，给出保留、合并、暂缓的原因。24/16/48是原始候选数量，不承诺去重后全是不同玩法，更不要求同时实现全部。

每个候选用以下字段，不能只有名称和“提高10%”：

| 字段 | 必须说清 |
|---|---|
| 玩家幻想与位置 | 玩家为什么想建/招募；占哪个现有位或归属哪栋建筑，不自动扩成几十个槽 |
| 条件与成本 | 何时解锁，消耗哪些现有资源/人口/点数，是否有持续成本及其上限 |
| 收益与独特动作 | 改变哪种决策；新增的是交易、保护、调度、改路线，还是纯产量 |
| 代价/失败情况 | 什么时候不划算，资源不够时怎样降级，不暗扣到负数 |
| 组合与反例 | 至少一个协同对象和一个不能无脑叠加的场景 |
| 操作负担 | 手动/委任如何用，预计每游戏月需要几次操作，是否会打断办公 |
| 可视与反馈 | 小窗如何显示状态，如何预览效果、解释无法执行 |
| 证据与原创改写 | 参考的具体机制和来源，以及本项目真正不同的用途/限制 |
| 开发成本与验证 | 依赖的系统、粗略实现点数、最小可玩验证、通过/失败指标 |

单位还需写职业、性格、能力、寿命/死亡后影响和委任权限；精灵宰相是长期跟随者，不能被普通人才寿命系统杀死。技能需写前置、点数成本、稀有资源条件、效果作用时机与互斥/叠加规则；基础技能继承可重分配的长期设计保留，高级技能不凭跨局点数跳过稀有条件。

建筑、单位、技能应共同构成路线。例如“粮食不足时，用木材换粮应急”“建立据点换稳定矿石，但承担驻军和失守风险”“委任谨慎将军保兵，与贪利将军争取战利品形成区别”。这些只是设计方向，不是已实现的效果或借用某款游戏的事实。

## 选取与实验规则

候选按五项各0—2分评估：独特决策、与现有循环结合、桌面低负担、数值可控、实现成本；每个分数给一句证据。单纯倍率堆叠、无成本收益、让玩家反复开面板、难以在小窗解释的方案扣分。

每台推荐前2个组合，并用一段操作过程说明“什么时候做、付出什么、结果怎样”。任务3汇总一张路线表：稳健农业、城镇贸易、冒险采矿等路线的启动成本、瓶颈、风险与反制；这些路线不是额外职业锁定。

本轮已经指定实现的试验种子为**商栈、前哨营地、农务官、将军**，加宰相向导与原三树扩展。各DSH可以根据研究完善这些种子的机制和数值，必须用实验数据说明；不等用户逐个批准才能做试验。其他候选先交纸面/数据/独立小样，不擅自将所有候选加入正式存档。

原三树各新增3节点，其中至少2个应改变策略或条件，而不只是倍率；新建筑两树各3节点，同样要求至少1个有代价的组合效果。新增节点先由任务3校验前置有向无环、资源成本和叠加范围，再由任务2接入同一规则来源。

评价不是“玩家肯定喜欢”：要给可测假设，如同一资源预算下出现两条可行突破路线、委任后减少重复点击、连续若干月存在值得花资源的选择。无人实玩时只说模拟结果；不能把优化了数值等同于证明了乐趣。

## 24/48/72点交付

- 24点：来源与观察、每台完整候选清单、前2组合；启动相关原型/工具，不只交文案。
- 48点：指定种子可运行，技能和人才形成至少两条可比较路线；非本机主实现的候选交模块/界面样例或测量方案。
- 72点：依据同版本试玩/回放淘汰或修改方案，补代价、反馈和组合边界；用事实说明哪些保留、哪些仍待验证。

来源与研究只能证明观察；设计默认值、试验效果和最终决定分别标记。真实素材的许可记录与正式发售状态另行跟踪，不能把灵感来源当作资产商用授权。
