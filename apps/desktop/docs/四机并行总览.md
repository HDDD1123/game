## 同一起点，独立分支

任务分发分支为 `codex/dsh-four-tasks-20261113`，游戏代码基线为 `d052b27`，包含文档补充 `e9ea0e7`。本次任务包只增加任务/接口约定，不把尚未实现的功能写成已有功能。

四台机器都从该分发分支开自己的工作分支，不从main或旧的v0.3分支开始。新机器建议单独检出；下面以任务1为例，其他机器只把目录和工作分支编号换成对应任务：

```powershell
git clone --branch codex/dsh-four-tasks-20261113 --single-branch https://github.com/HDDD1123/game.git game-task1
cd game-task1
git switch -c dsh/task1-street-v05
git rev-parse HEAD
```

原有DSH也可以用新的独立目录，避免覆盖原工作目录。已有同名目录/分支时先查看状态，不强制删除或重置。各机使用自己获授权的GitHub身份，不复制别人的凭据。

先读根目录 `AGENTS.md`、`.agents/skills/kingdom-gamedev/SKILL.md`、本总览、自己的任务和 [四机接口约定](四机接口约定.md)。Godot固定4.6.3标准版；任务4的独立辅助程序不意味着改用Godot .NET版。

## 并行与整合顺序

四份任务现在都能开工：任务1使用现有游戏内核，任务2有自己的时间演示场景，任务3对固定基线运行实验，任务4有自己的打字演示场景。任务1不等待任务2，任务4也不等待主界面按钮。

各机只推自己的分支，不互相合并、不推main、不自行覆盖集成包。交付后由GPT先审查任务2的时间/存档，再合入任务1，并接上开始/暂停与月内进度；审查任务4后接入默认关闭的打字功能；最后用任务3的工具在集成版本重跑。任务3的候选数值经审查后另行选取，不自动进入游戏。

最终接线由GPT负责：将各模块变成同一个可玩的v0.5预览版，再交原有DSH完成Windows最终导出。独立模块通过不等于集成版通过。任务4若被平台问题卡住，可先交付其协议和演示，整合版保持该功能关闭，其他三项继续。

1. 推送分支，报告基线提交、最终提交、改动文件、启动/测试命令和实际结果。

4. 任务包/演示ZIP可放本地 `dist/`，附SHA-256和来源提交；不把EXE、大视频、编译缓存塞进源码历史。小型素材、CSV、测试样例与必要截图可入库。
