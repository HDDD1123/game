## 006B最小实现：先接农田，统一图片组件

先读根目录 `AGENTS.md`、项目技能入口，按需读 `godot-ui-control`、`create-game-assets`。这轮目标是“替换一张图片就能改变农田外观，所有原有操作仍可用”。

1. 接通 `data/building_slots.json` 中已有的 `texture` 字段。民居、农田、铁匠铺使用可复用的图片显示组件或同一构建方法；先仅给农田接一张明确标记为临时素材的透明PNG，其余维持文字占位。
2. 空路径、文件缺失、加载结果不是Texture2D时，回退文字占位并保持操作。不要每帧读取图片或重新创建控件。有效图片必须在导出资源包内可加载，不能依赖开发电脑的绝对路径。
3. 图片和装饰不吞鼠标事件；点击可见农田仍是“有成熟先收取，否则助耕”。升级走“农田详情”，研究走独立入口；不得把点击改成打开详情。
4. 保留可见的待收批数/粮食量、生长状态，以及额度/暂停提示。用文字或轻量高亮区分生长中、可收取、已满3批，不要求三套新图。4个预留位不增加生产和升级。
5. 先测量720宽、960宽、全宽时的图片与文字可用区域，记录Godot窗口尺寸和Windows缩放。街景仍约280高；图片保持比例、统一底部基线，不靠拉高整个街景解决溢出。技能和详情面板按既有规则展开。
6. 增加简短美术规格与资产清单：文件路径、实际显示矩形、源图尺寸、视角、基线、透明底、缩放方式、来源/工具/日期、许可信息、临时或正式状态。先验证一个样例，正式风格尚未确定，不批量制作升级外观。

没有现成正式美术不必停工；使用来源清楚的临时素材验证。没有可用出图工具时保持明确的占位，报告实际完成的图片加载能力，不把文字占位称为完成美术。

## 在最终试玩包上补齐真实输入检查

使用临时测试存档/窗口配置，先保护玩家原存档。以下可以由DSH的桌面控制工具发送操作系统鼠标输入；报告写明是人工还是操作系统输入自动化。`pressed.emit()`、直接调用函数不计入。若缺少该工具，如实记为未测，并提供可由用户执行的下列短清单，不能把承诺“明天补”写成已完成。

| 场景 | 操作及应看到的结果 |
|---|---|
| 流民与暂停 | 在街景推进到来访，分别验证接纳/拒绝；未决时不能推进，成熟粮仍可收取；缺床时能进入住房扩建 |
| 农田与图片 | 点击农田的图像区域而非专门按钮，验证先收取、无成熟时助耕、当月20%上限及暂停提示；从详情升级后数值立即更新 |
| 技能树 | 前置解锁后无需重开面板即可点分支，一次只扣一点；滚动后刷新不跳回，文字清晰 |
| 缺粮 | 区分粮仓与待收，核对直接推进/先收粮的预览；危险状态若用构造存档，明确标注 |
| 布局 | 分别720宽、960宽及全宽测试，尤其“流民等待＋口粮警报”；7位、按钮、提示可见且能点，图片不遮挡；记录实际尺寸和缩放 |
| 窗口与保存 | 保存/读取一致，退出取消保留窗口，置顶开关/窗口记忆有效，窗口不挡任务栏；在其他应用工作时不抢焦点。保存失败提示使用独立临时路径验证 |

可录一段视频标记时间点，也可分段；录屏失败时，逐项记录实测操作和前后截图，明确视频缺失。用能证明行为的材料验收，不让录制工具问题遮住真实输入是否通过这一事实。至少补一张包含任务栏的桌面截图，隐藏无关私人窗口。
