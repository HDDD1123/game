# 四机接口约定：v0.5预览版（72点任务R2）

日期：2026-11-13。状态：**设计完成、待实现**。A/B保留原时钟与后台输入契约，C以后扩展72点版的模块接线、启动与新玩法。现有可用接口仍以 [核心接口](核心接口.md) 为准；本文的新接口不能冒称已经在源码中存在。试验默认值由本轮任务确定，不等于正式版最终数值。

## 共同规则

- 农田最多暂存3批，手动收取；待收不等于粮仓。点击与打字共享现有当月加速额度，不改变 `farm_buffer.gd` 里的倍率/上限。
- 重大事件冻结时间和生长，但仍能收成熟粮、建设和处理事件；游戏关闭/系统睡眠不补进度。失去前台焦点不等于暂停，否则无法边工作边挂机。
- 人口、月末收支、战斗、技能效果仍由Kingdom计算。UI不复制公式，平台输入不直接改粮食/人口。
- 各任务保留现有方法签名及控件入口；扩展状态由任务2统一维护，玩法定义/计划由任务3提供，其他模块不另建权威资源余额。

## A. 任务2提供的时间接口

默认1个游戏月为 **150000毫秒（150秒）**，与此前约20小时对应40游戏年的设想一致。预览阶段只做1倍速；测试通过注入经过时间快速验证，无需真的等几十分钟。不要把游戏速度选项加入本轮必做范围。

| 接口 | 约定 |
|---|---|
| `game.act("set_auto_running", {"enabled": bool})` | 开启/暂停自动时间；沿用 `{ok,message,state,view}` 返回格式。重复设置幂等，类型错误不变状态 |
| `game.tick(elapsed_ms: int)` | 输入本次在线有效毫秒，返回 `{ok,changed,months_advanced,message}`；不在每次tick深复制全部记录 |
| `game.set_time_blocked(reason: String, blocked: bool)` | 会话级阻塞集合；如退出确认、读写存档，各原因独立增删，不能清除别人的阻塞 |
| `game.view().clock` | `{running, blocked, pause_reasons, month_elapsed_ms, month_duration_ms, remaining_ms, month_progress, can_step}`；进度0到1，原因使用稳定字符串 |
| `game.act("advance_month")` | 自动运行时拒绝；手动暂停时明确跳到**本月结束**，只生产剩余时长的农作物。整月起点时与旧操作效果一致 |

`running` 是玩家是否开启自动；`blocked` 是事件/结束/外部阻塞是否阻止推进，不包含玩家主动暂停。`pause_reasons` 可包含 `manual`、`event`、`ended`、`external:<reason>`。`can_step` 仅在自动关闭、无事件、未结束、无外部阻塞时为真。外部阻塞原因按唯一键存储，重复增加不叠加次数。

新局、重新开始、成功读档后自动时间默认为关闭；月内进度恢复后由玩家点击开始。事件解决时，若原本自动开启，则下一次有效tick继续；用户主动暂停不能被事件关闭所覆盖。读取失败必须连同原有自动运行状态一起保持不变。外部阻塞由调用者释放，读取不能顺手清掉退出确认的阻塞。

`tick` 接受0到1000毫秒；0无变化，越界不推进且明确返回失败。UI/演示用短间隔单调时钟增量，不用系统日期差；一次间隔超过1000毫秒视为挂起/长卡顿，该段直接丢弃并重置采样，不拆成大量tick追赶。正常小数毫秒在驱动端累积，避免每帧取整导致时间变慢。主窗口失焦仍正常取在线增量。

有效tick推进月内时间，同时按现有技能修正后的自然生长速度产生工作量。使用整数余量累计，确保拆成小步与整段推进结果一致；暂停不累计，农田满/无人劳动时丢弃当时不能使用的生长量，不为收获后存一笔加速。点击/打字只增加农作物工作量，不推进日历。

到月界时先完成该月最后一段生长，再沿用“扣口粮与木材收入→饥饿伤亡→月份切换/重置加速额度→战斗→来访”的顺序。月结算不能再额外生长整整一批。批次粮食量以实际成熟时的当前季节、技能和劳动条件计算；已成熟的批次不追溯涨价。月界发生待决事件/结束时立即停止，余下tick时间丢弃，不留到事件处理后补跑。

主动暂停、外部阻塞与事件等待期间助耕都不产生收益；成熟粮仍可手动收取（王国已经结束的既有禁止操作规则不变）。关闭自动时间后依然可以用 `advance_month` 手动测试，不另做第二套自然生长逻辑。旧的“手动模式也能点击助耕”测试在任务2中明确改为先开启自动模式再验证；不得无说明删断言。

### 时间存档

升级到格式5，默认 `user://kingdom-save-v5.json`。游戏snapshot新增：

```json
{"clock":{"version":1,"month_elapsed_ms":0,"growth_remainder":0}}
```

`month_elapsed_ms` 和 `growth_remainder` 均为0至149999的整数。每段自然工作量用 `(elapsed_ms * 本月每150秒的自然工作量 + growth_remainder)` 除以150000，整数部分交给农田、余数保留；满田/无人劳动时余数也不积攒。时钟新局为0；仅整月跳过的兼容操作也走同一入口。完成整个存档校验后才能替换状态。

自动运行开关、外部阻塞、平台输入缓存、进程句柄、系统时间戳不写入存档。格式4迁移保留农田进度/待收/当月助耕用量/技能/事件/远征，新增clock置0，不重置本月额度或追补产出；格式3经原迁移规则补齐再进入5。

默认读取优先级为5→4→3，只有较新文件**不存在**才试较旧文件；新版存在但损坏应报错，不能静默用旧档或备份顶替。明确传入路径时只处理该文件。保留旧文件，保存写出5；测试路径继续可注入，当前 `.tmp`/`.bak` 保全策略保持，失败保持游戏进度和运行状态。v5缺clock属于坏档，不能伪装成旧档自动修复。

## B. 任务4提供的后台活动接口

`apps/desktop/platform/typing/typing_bridge.gd` 提供以下接口，平台层不依赖Kingdom：

| 接口 | 约定 |
|---|---|
| `start(helper_path: String) -> Dictionary` | 显式开启，返回 `{ok,message}`；默认未启动，重复开启不创建第二进程 |
| `stop() -> void` | 幂等关闭、清空计数，辅助进程退出；桥接节点销毁时也清理 |
| `drain_count() -> int` | 取出当前未消费汇总并清零，同一批只返回一次 |
| `status() -> Dictionary` | `{enabled,helper_running,last_error}`；只报告开关、进程及错误，不含输入内容 |

本地助手stdout每250毫秒至多发一行，例如 `{"v":1,"seq":7,"count":12}`。只发整数计数和递增序号；count范围0至1000，单行最长512字节。桥接严格校验字段类型、上限和序号，拒绝重复/倒退序号、畸形/超长行，累积计数有上限；新进程重新建立会话序号，不把旧管道残留带入新会话。stdout只用于协议，诊断走stderr且不含键值。

可用 stdin 的 `{"v":1,"command":"shutdown"}` 请求退出；父进程结束、管道断开、关闭开关时都要有可靠退出机制。Godot管道读取不得阻塞主线程；先核实4.6.3可用API，不凭新版本示例假定存在。

统计非修饰键的一次有效按下，忽略按住产生的系统重复；键码仅允许在本机内存中用于判断重复/释放，不输出、不保存具体按键、文字、窗口标题或剪贴板，不上传。无网络、无自启动、普通用户可运行；不要为了测试关闭系统防护或要求全局管理员权限。

未来GPT接线时持续取走汇总；仅在时间允许生长时提交 `game.act("assist_farm", {"source":"typing","count":n})`。暂停/关闭/满田期间的计数丢弃，不攒到恢复后发放；点击与打字额度最终由core统一限制。输入桥不负责粮食、时间或加速倍率。

仅调用drain不能清掉助手尚未发出的半批数据。本轮在暂停/满田时停止助手，恢复可生长时建立新会话，清掉管道/解码/计数缓存。调用方单独保留“用户已打开功能”的意图，只有该意图仍开启才允许恢复助手；不得把自动恢复变成首次偷偷开启监听。

## C. 任务1与任务3的独立交付约定

任务1的图片继续由 `data/building_slots.json` 的 `texture` 路径驱动，空/坏路径回退文字。保持7位与现有点击路线，保留外部测试用到的主要控件引用。启用预览内容时，在两个预留位显示商栈与前哨营地，余两位保留；关闭预览内容的新局仍是原3位。主界面在模块未就绪时可用独立fixture开发，但不能把fixture数据带入真实游戏。

任务1负责实际UI接线、任务2负责Kingdom内核接线、任务4负责平台服务接线；按总览在独立integration分支合入并回归，GPT作规则/接口审查。不是等所有工作完成后再把全部接线留给GPT。

任务3的模拟器只通过 `act/snapshot/view` 和公开报价读取、驱动游戏，不操作 `_state`。第一阶段可基于手动月结算固定基线，输出标明提交号；之后在固定集成版本重跑连续时间/新内容，旧曲线不能冒充新时钟实测。候选配置只在隔离实验工程加载，生产数值由任务2依据被选中的实验结果统一适配。

## D. 唯一会话与启动服务

### 时间与动作入口（任务2提供，任务1装配）

`apps/desktop/runtime/session_controller.gd` 继承Node，管理一个Kingdom实例，不创建第二个世界。目标公开接口：

| 接口 | 作用 |
|---|---|
| `attach_game(game: RefCounted) -> void` | 注入现有Kingdom、重置采样；重复绑定不添加第二计时器，不自动开始时间 |
| `command(name: String, args: Dictionary = {}) -> Dictionary` | 转交game.act并返回原结果，成功后通知界面；无效指令不变状态 |
| `set_block(reason: String, blocked: bool) -> void` | 转交时间阻塞集合；关闭确认、加载等各有唯一原因，释放自己的原因 |
| `refresh_after_load() -> void` | 成功读档后重置采样/输入会话并发通知，不推进游戏；失败读档不调用 |
| `state_changed` 信号 | 通知UI按需读取view；连续进度最多每秒4次，重大选择/命令结果立即通知 |

此控制器是主游戏唯一tick调用方。任务1的UI不能再直接加生长Timer，任务4的助手不能推进时间。每次有效在线增量遵守A的丢弃/暂停规则；隐藏窗口只是渲染状态，不自行暂停世界。独立测试/演示可各自建控制器，但不能同时驱动同一个Kingdom。

任务4提供 `platform/bootstrap/startup_service.gd` 和 `platform/settings/settings_store.gd`。启动服务给出 `inspect_saves(save_store)` 的只读文件存在/版本/错误结果，不以存在性宣称可读；真正载入调用任务2SaveStore，校验通过才切换状态。任务1负责首屏新建/继续、错误重试与恢复选项；新建操作不得删除旧存档。偏好与窗口位置分别有唯一写入者，不重复维护两份同义字段。

设置文件可用独立版本化 `user://preferences-v1.json` 保存音量、字号、减少动画等；原窗口位置/尺寸文件由现有主UI继续维护。自动运行与监听每次启动默认关闭，不把上次开启状态偷偷恢复。任务4的纯窗口辅助方法可返回推荐工作区矩形，任务1负责真正设置窗口，避免两个脚本互相拉扯。

主入口/project.godot由任务1修改，export_presets由任务4修改。旧场景仍应能独立实例化用于测试；外部服务不可用时保持基础功能可运行并说明缺口，不吞异常后返回成功。

## E. 预览内容、目录与原子提交

### 启用范围

新增 `game.act("new_game", {"enable_content_preview": bool})`，只用于玩家明确新建；默认false。旧 `restart` 保留且使用当前局的内容模式。内容模式写入存档，不能在同一局中途关闭来删除驻军/人才/建筑债务；回到基础模式应明确新建，不修改旧档。所有新功能在实验/预览模式验证，基础经营继续可用。

### 任务3模块接口

`core/content/content_catalog.gd` 提供 `catalog() -> Dictionary` 与 `validate() -> Dictionary`；目录包括建筑、人才、技能、事件及版本。定义须有稳定id、显示文案、解锁条件、成本、效果和前置；引用通过白名单校验，不能用eval或加载任意脚本执行数据。

`core/content/content_rules.gd` 提供 `plan(context: Dictionary, action: Dictionary) -> Dictionary`，目标返回 `{ok, problem, costs, effects, facts}`。context为深复制只读输入，action含kind和ID/参数，plan不读取文件/时钟、不随机抽取、不修改传入状态。条件与价格只在此计划入口计算一次；预览与执行使用同一计划逻辑。

effects是带类型的有限计划，不是任意_state补丁。至少覆盖资源增减、建筑建成、驻军变化、人才委任、技能解锁、事件旗标等已经支持的类型；任务2实现白名单校验/提交器。先验证整个计划及资源/人口/上限，再一次提交；某条失败不能已经扣掉前面的木材。effect/fact具稳定来源id，同一月/同一事件只提交一次。

内容参数的最终数值由任务3写入目录并附实验，任务2不能在UI之外再写一份不同价格。旧基础计算与新修正明确组合顺序，不能重复应用倍率；UI只显示核心给出的最终报价和原因。

### 对外命令与视图

| 命令 | 参数与主要约束 |
|---|---|
| `construct_building` | `{building_id}`；条件、价格、已建/未建由核心校验 |
| `trade_resources` | `{building_id, offer_id, quantity}`；正整数、有月限额、净交易不套利 |
| `recruit_talent` | `{candidate_id}`；真实候选一次受理，职业/性格/能力在权威招募流程确定并保存 |
| `assign_talent` | `{talent_id, assignment_id}`；同一人口不重复任职/驻军/出征，死亡者不能任职 |
| `set_policy` | `{policy_id, attitude, overrides}`；态度为开放/标准/保守的稳定ID，默认阈值来自目录，override严格校验 |
| `resolve_event` | `{event_id, choice_id}`；预览/校验/执行共享计划，过期或旧ID不生效 |
| `unlock_content_skill` | `{tree_id, node_id}`；前置、点数、资源一次扣除；旧unlock_skill保持兼容 |
| `quote_content` 方法 | `(action: Dictionary) -> Dictionary`；调用同一plan返回成本/效果/问题，不改变世界或随机状态 |

新动作进入现有act回包格式，不创建另一个有独立余额的“新建筑小游戏”。`view()`扩展 `features`、`buildings`、`talents`、`policies`、`events`、`content_skills`、`history`，任务2提供字段说明和示例fixture；未知/未实现内容显示disabled及原因。扩展技能与旧三树在核心合成后给UI一个可展示目录，不让两个解锁接口重复消费同一个节点。

旧流民pending与新事件队列必须指向同一受理事实；旧接纳/拒绝命令保留桥接，但不能两处各加一次人口。重要事件默认暂停，期限按游戏月计算；暂停后期限也停止，普通未暂停事件按配置到期处理。多事件有顺序与有界队列，触发渲染不会重新抽奖或刷新期限。

自动任务只在已招募、存活并委任时执行；月度任务有来源键和有界次数。将军只重复已通关路线，首次挑战仍请求玩家；撤退由个性和事先可见的条件在房间边界决定，不增加随时召回按钮。自动收取是农务官的委任能力，不取消基础手动规则。

农务官在允许生长的有效tick中、农田成熟后至多提交一次收取；同一tick到月界时先处理已授权的成熟收取再扣口粮，不额外产粮。手动“到月末”是显式时间步，可执行对应已委任任务；静止暂停期间不主动运行自动任务。将军个性只在授权目标内决策，不能把“清理已通关入口”擅自改成首次探索新区域。

## F. 扩展存档与叙事事实

格式5除A的clock外，增加版本化 `extensions`：`schema_version`、`enabled`、`content`、`talents`、`policies`、`events`、`rng`、`history`。具体子字段由任务2在T2-01发布可校验schema及中性默认值；任务3/4按此供数据，不各自发明第二份人才名单。只有已实现的状态进入实际存档，不能用任意Dictionary绕过类型/ID/范围验证。

旧3/4档迁移时扩展默认关闭且中性，不追补建筑、人才、收益或年龄。若各机已有clock-only试验v5，将其作为明确的schema0样例，在完整校验旧字段后一次补齐schema1；缺clock或非法已存在扩展字段仍是坏档。schema1里的必需字段缺失不能静默猜值。版本升级通过纯迁移函数；读取全部成功后才替换世界和随机状态。

游戏保存包含在途/驻军/人才年龄及职业个性、委任、事件到期月/已处理标识、交易月额度、内容技能与确定性随机状态；不存Node、进程句柄、监听计数或系统时间戳。人口包含城内、在途和驻军，岗位不能超出可用池。职业增益只计算一次，死亡/离任立即撤销；精灵宰相不走普通人才死亡路径。

若随机算法使用64位种子/状态，使用经过校验的十进制字符串或其他无损表示保存，不能经JSON浮点损失精度；事件/人才ID来自持久计数，不来自渲染次数或真实时钟。随机快照恢复前后用同一输入应产生同样结果。

任务2提供结构化history事实：稳定ID、游戏月、类型、结果与必要数量/主体ID。至少有远征出发/返回/失败、伤亡原因、建设、人才招募/死亡、事件选择、据点得失、阶段成就和结束原因。持久累计计数与有限明细分开；40条短日志截断不等于过去没发生。

任务4的叙事生成器只读事实，`render_history(facts: Array, summary: Dictionary) -> Dictionary` 返回条目与已证实的结局描述，不改状态。没有证据不作责备式归因，不用运行时AI补事实。主动隐退/继承尚未实现时相关模板只能在明确标注的fixture中预览，正式界面无虚假可用按钮。当前局手记可保存；跨局历史/遗产另有版本边界，不能借本任务隐式改变已确认的继承规则。

## G. 交付与协议变更

以上新增接口均为目标而非完成声明。负责人可在不改语义的前提下调整内部实现；变更公开名称/字段先更新自己交付目录的接口差异与示例，并通知整合负责人，不能一边实现另一边继续按旧名接线。24点发布核心和目录schema，48点完成真实玩法接线，72点完成组合/坏档/长程验证。

阶段整合使用固定提交和ready清单；主UI由任务1写、核心由任务2写、内容模块由任务3写、平台/叙事服务由任务4写。共同文件与审查标准以 [总览](四机并行总览.md) 为准，不通过静默吞错、返回假成功或抹掉旧测试消除冲突。
