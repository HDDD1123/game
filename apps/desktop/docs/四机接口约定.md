# 四机接口约定：v0.5预览版

日期：2026-11-13。状态：**设计完成、待实现**。这是本轮任务的目标接口，现有可用接口仍以 [核心接口](核心接口.md) 为准。涉及新功能的技术默认值由GPT为本轮试验确定，不等于正式版数值。

## 共同规则

- 农田最多暂存3批，手动收取；待收不等于粮仓。点击与打字共享现有当月加速额度，不改变 `farm_buffer.gd` 里的倍率/上限。
- 重大事件冻结时间和生长，但仍能收成熟粮、建设和处理事件；游戏关闭/系统睡眠不补进度。失去前台焦点不等于暂停，否则无法边工作边挂机。
- 人口、月末收支、战斗、技能效果仍由Kingdom计算。UI不复制公式，平台输入不直接改粮食/人口。
- 各任务保留现有方法签名及控件入口，除任务2明确扩展的时间/存档外不另建一套状态。

## A. 任务2提供的时间接口

默认1个游戏月为 **150000毫秒（150秒）**，与此前约20小时对应40游戏年的设想一致。预览阶段只做1倍速；测试通过注入经过时间快速验证，无需真的等几十分钟。不要把游戏速度选项加入本轮必做范围。

| 接口 | 约定 |
|---|---|
| `game.act("set_auto_running", {"enabled": bool})` | 开启/暂停自动时间；沿用 `{ok,message,state,view}` 返回格式。重复设置幂等，类型错误不变状态 |
| `game.tick(elapsed_ms: int)` | 输入本次在线有效毫秒，返回 `{ok,changed,months_advanced,message}`；不在每次tick深复制全部记录 |
| `game.set_time_blocked(reason: String, blocked: bool)` | 会话级阻塞集合；如退出确认、读写存档，各原因独立增删，不能清除别人的阻塞 |
| `game.view().clock` | `{running, blocked, pause_reasons, month_elapsed_ms, month_duration_ms, remaining_ms, month_progress, can_step}`；进度0到1，原因使用稳定字符串 |
| `game.act("advance_month")` | 自动运行时拒绝；手动暂停时明确跳到**本月结束**，只生产剩余时长的农作物。整月起点时与旧操作效果一致 |

`running` 是玩家是否开启自动；`blocked` 是事件/结束/外部阻塞是否阻止推进，不包含玩家主动暂停。`pause_reasons` 可包含 `manual`、`event`、`ended`、`external:<reason>`。`can_step` 仅在自动关闭、无事件、未结束、无外部阻塞时为真。外部阻塞原因按唯一键存储，重复增加不叠加次数。

新局、重新开始、成功读档后自动时间默认为关闭；月内进度恢复后由玩家点击开始。事件解决时，若原本自动开启，则下一次有效tick继续；用户主动暂停不能被事件关闭所覆盖。读取失败必须连同原有自动运行状态一起保持不变。外部阻塞由调用者释放，读取不能顺手清掉退出确认的阻塞。

`tick` 接受0到1000毫秒；0无变化，越界不推进且明确返回失败。UI/演示用短间隔单调时钟增量，不用系统日期差；一次间隔超过1000毫秒视为挂起/长卡顿，该段直接丢弃并重置采样，不拆成大量tick追赶。正常小数毫秒在驱动端累积，避免每帧取整导致时间变慢。主窗口失焦仍正常取在线增量。

有效tick推进月内时间，同时按现有技能修正后的自然生长速度产生工作量。使用整数余量累计，确保拆成小步与整段推进结果一致；暂停不累计，农田满/无人劳动时丢弃当时不能使用的生长量，不为收获后存一笔加速。点击/打字只增加农作物工作量，不推进日历。

到月界时先完成该月最后一段生长，再沿用“扣口粮与木材收入→饥饿伤亡→月份切换/重置加速额度→战斗→来访”的顺序。月结算不能再额外生长整整一批。批次粮食量以实际成熟时的当前季节、技能和劳动条件计算；已成熟的批次不追溯涨价。月界发生待决事件/结束时立即停止，余下tick时间丢弃，不留到事件处理后补跑。

主动暂停、外部阻塞与事件等待期间助耕都不产生收益；成熟粮仍可手动收取（王国已经结束的既有禁止操作规则不变）。关闭自动时间后依然可以用 `advance_month` 手动测试，不另做第二套自然生长逻辑。旧的“手动模式也能点击助耕”测试在任务2中明确改为先开启自动模式再验证；不得无说明删断言。

### 时间存档

升级到格式5，默认 `user://kingdom-save-v5.json`。游戏snapshot新增：

```json
{"clock":{"version":1,"month_elapsed_ms":0,"growth_remainder":0}}
```

`month_elapsed_ms` 和 `growth_remainder` 均为0至149999的整数。每段自然工作量用 `(elapsed_ms * 本月每150秒的自然工作量 + growth_remainder)` 除以150000，整数部分交给农田、余数保留；满田/无人劳动时余数也不积攒。时钟新局为0；仅整月跳过的兼容操作也走同一入口。完成整个存档校验后才能替换状态。

自动运行开关、外部阻塞、平台输入缓存、进程句柄、系统时间戳不写入存档。格式4迁移保留农田进度/待收/当月助耕用量/技能/事件/远征，新增clock置0，不重置本月额度或追补产出；格式3经原迁移规则补齐再进入5。

默认读取优先级为5→4→3，只有较新文件**不存在**才试较旧文件；新版存在但损坏应报错，不能静默用旧档或备份顶替。明确传入路径时只处理该文件。保留旧文件，保存写出5；测试路径继续可注入，当前 `.tmp`/`.bak` 保全策略保持，失败保持游戏进度和运行状态。v5缺clock属于坏档，不能伪装成旧档自动修复。

## B. 任务4提供的后台活动接口

`apps/desktop/platform/typing/typing_bridge.gd` 提供以下接口，平台层不依赖Kingdom：

| 接口 | 约定 |
|---|---|
| `start(helper_path: String) -> Dictionary` | 显式开启，返回 `{ok,message}`；默认未启动，重复开启不创建第二进程 |
| `stop() -> void` | 幂等关闭、清空计数，辅助进程退出；桥接节点销毁时也清理 |
| `drain_count() -> int` | 取出当前未消费汇总并清零，同一批只返回一次 |
| `status() -> Dictionary` | `{enabled,helper_running,last_error}`；只报告开关、进程及错误，不含输入内容 |

本地助手stdout每250毫秒至多发一行，例如 `{"v":1,"seq":7,"count":12}`。只发整数计数和递增序号；count范围0至1000，单行最长512字节。桥接严格校验字段类型、上限和序号，拒绝重复/倒退序号、畸形/超长行，累积计数有上限；新进程重新建立会话序号，不把旧管道残留带入新会话。stdout只用于协议，诊断走stderr且不含键值。

可用 stdin 的 `{"v":1,"command":"shutdown"}` 请求退出；父进程结束、管道断开、关闭开关时都要有可靠退出机制。Godot管道读取不得阻塞主线程；先核实4.6.3可用API，不凭新版本示例假定存在。

统计非修饰键的一次有效按下，忽略按住产生的系统重复；键码仅允许在本机内存中用于判断重复/释放，不输出、不保存具体按键、文字、窗口标题或剪贴板，不上传。无网络、无自启动、普通用户可运行；不要为了测试关闭系统防护或要求全局管理员权限。

未来GPT接线时持续取走汇总；仅在时间允许生长时提交 `game.act("assist_farm", {"source":"typing","count":n})`。暂停/关闭/满田期间的计数丢弃，不攒到恢复后发放；点击与打字额度最终由core统一限制。输入桥不负责粮食、时间或加速倍率。

仅调用drain不能清掉助手尚未发出的半批数据。本轮在暂停/满田时停止助手，恢复可生长时建立新会话，清掉管道/解码/计数缓存。调用方单独保留“用户已打开功能”的意图，只有该意图仍开启才允许恢复助手；不得把自动恢复变成首次偷偷开启监听。

## C. 任务1与任务3的独立交付约定

任务1的图片继续由 `data/building_slots.json` 的 `texture` 路径驱动，空/坏路径回退文字。保持7位与现有点击路线，保留外部测试用到的主要控件引用；主界面暂不调用尚未合入的时间/输入模块。新模块接线由GPT在集成分支完成。

任务3只通过 `act/snapshot/view` 和公开报价读取、驱动游戏，不操作 `_state`。本轮模拟基于手动月结算的固定源码，输出标明提交号；集成连续生长后必须重跑，旧曲线不能冒充新时钟实测。候选配置只在隔离的实验工程中加载，生产 `balance.gd` 不改。
