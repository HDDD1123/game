# 任务4：启动、桌面运行、后台输入与叙事交付（72点）

负责人：新DSH-C。分支：`dsh/task4-typing-v05`。修订R2。目标是让游戏容易启动、能安静地在桌面运行、遇错可恢复，并为宰相向导和真实王国历史提供可用组件。

先读 [总览](四机并行总览.md)、[接口](四机接口约定.md)、[研究规范](同类游戏调研与特色设计规范.md)。按阶段用 `input-systems`、`performance-optimization`、`godot-export`；启动/叙事阶段再按需读取相关技能。全局输入不由InputMap提供，Godot仍用4.6.3标准版。

## 关键边界

- 启动服务不自动跳月、不静默读坏档旧版本、不清空玩家存档；自动时间与打字开关每次启动都按项目安全默认，输入需显式开启。完整桌面窗口操作仍由任务1主UI持有，服务不再偷偷连接一份关闭事件。
- 启动优化优先检查重复加载、字体回退、大图/历史内容的过早载入和同步扫描；可延迟的内容等首个可操作界面后按需加载。每个改动比较首个可操作时间与首次使用卡顿，不能把等待简单挪到第一次点击后就声称优化成功。
- `tools/windows-typing/` 可用独立C#/.NET/原生Win32等已有工具链，写清构建/运行依赖。Godot项目不改.NET版，不要求管理员、不关闭系统防护。仅内存键码用于去重，不记录按键序列、窗口标题或剪贴板。
- 管道只发约定协议，不把调试文本混在stdout。暂停/满田停止助手并清缓存，只有用户意图仍开启才恢复新会话；输入桥不拥有游戏数值或时间循环。
- 性能报告要有源码、硬件、分辨率/DPI、驱动/渲染模式、采样窗口和基线；能测才报，不承诺统一CPU百分比。明显回退给出原因和后续负责人，不能为了好看改测试场景。
- 宰相组件只读取事实/发出动作请求；任务2拥有世界状态，任务1持有主面板。史书不能只看最多40条日志就断言早年“从未”发生某事；用持久计数/事实，没有就省略判断。主动隐退/跨局继承本轮未实现时只做fixture预览，正式界面不伪造入口。
- 8类结局模板是可验证文案素材，不意味着本轮实现8种新的失败机制。使用虚构案例测试必须标注，最终文本来自真实事件原因、成就和损失。
